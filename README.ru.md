## Обзор

GitHub Activity Visualizer - это фронтенд-дашборд, использующий **GitHub REST API** и **D3.js** для визуализации любого публичного профиля

Введите имя пользователя → получите полный разбор его активности за секунды. Переключитесь на вкладку **Compare**, чтобы сравнить два профиля рядом

Все запросы к GitHub API проходят через небольшой **Cloudflare Worker**, который хранит токен API как серверный секрет и кэширует ответы в Workers KV. Эффективный лимит: 5 000 запросов/ч от GitHub, но на практике почти каждый запрос обслуживается из кэша

**Попробуйте:** [`?user=jarryuser`](https://jarryuser.github.io/github-visualizer/?user=jarryuser) · [`?user=torvalds`](https://jarryuser.github.io/github-visualizer/?user=torvalds) · [`?tab=compare&a=torvalds&b=gaearon`](https://jarryuser.github.io/github-visualizer/?tab=compare&a=torvalds&b=gaearon)

## Технологический стек

| Слой | Инструмент | Почему |
|---|---|---|
| Язык | TypeScript 5.3 | Безопасность типов для всех ответов API |

| Хостинг фронтенда | GitHub Pages + gh-pages | Деплой одной командой, бесплатный хостинг |

## Архитектура

```
┌──────────────┐   fetch /users/foo   ┌────────────────────────────┐
│   Browser    │ ───────────────────▶ │  Cloudflare Worker proxy   │
│ (GitHub Pgs) │ ◀─────────────────── │  github-visualizer-proxy   │
└──────────────┘     JSON (cached)    │                            │
                                       │   ┌────────┐  KV lookup    │
                                       │   │   KV   │ ◀──────────── │
                                       │   │ CACHE  │ ──────────▶   │
                                       │   └────────┘   (hit/miss)  │
                                       │                            │
                                       │   on miss ↓ Bearer <secret>│
                                       └─────────────┬──────────────┘
                                                     │
                                                     ▼
                                             api.github.com
```

Браузер никогда не хранит токен GitHub. Он знает только URL Worker-а
Worker имеет список разрешённых трёх маршрутов GitHub; всё остальное возвращает 404

## Начало работы

```bash
git clone https://github.com/jarryuser/github-visualizer.git
cd github-visualizer
npm install

# Фронтенд:
npm run dev        # → http://localhost:5173 (по умолчанию использует развёрнутый Worker)

# Worker (опционально - только если вы хотите редактировать прокси):
cp .env.example .env                # устанавливает VITE_PROXY_URL=http://localhost:8787
npm run worker:dev                  # → http://localhost:8787
```

Откройте приложение, введите любое имя пользователя GitHub, нажмите **View profile**. Или откройте вкладку **Compare**, чтобы сравнить два профиля рядом

## Развёртывание

### Фронтенд → GitHub Pages

```bash
npm run deploy
```

Обновляет `https://jarryuser.github.io/github-visualizer/` примерно за 30 секунд.

### Worker → Cloudflare (первая настройка)

```bash
# 1. Войдите один раз
npx wrangler login

# 2. Создайте пространство имён KV для кэширования
npx wrangler kv:namespace create CACHE
# → скопируйте полученный id в wrangler.toml вместо REPLACE_WITH_KV_NAMESPACE_ID

# 3. Сохраните токен GitHub как секрет Worker-а (НЕ в .env)
npm run worker:secret               # затем вставьте ваш fine-grained PAT

# 4. Разверните
npm run worker:deploy
```

Worker публикуется по адресу `https://github-visualizer-proxy.<your-subdomain>.workers.dev`
Обновите значение `PROXY_BASE` в `src/api.ts`, если вы используете другое имя

### Обновление существующего развёртывания

```bash
npm run worker:deploy   # разворачивает изменения worker/index.ts
npm run deploy          # разворачивает изменения фронтенда
```

### Создание GitHub токена

GitHub → Settings → Developer settings → Personal access tokens → **Fine-grained tokens** → Generate. Токену нужно только разрешение **`Public Repositories (read-only)`**. Вставьте его один раз через `npm run worker:secret`; с тех пор он хранится в Cloudflare и никогда не попадает в git

## Переменные окружения

| Где | Переменная | Назначение |
|---|---|---|
| `.env` (браузер, только локальная разработка) | `VITE_PROXY_URL` | Переопределить URL Worker-а при разработке с локальным Worker-ом. Если не установлено, фронтенд использует продакшн Worker |
| Секрет Worker-а (Cloudflare) | `GITHUB_TOKEN` | Fine-grained PAT, который Worker добавляет к запросам GitHub. Устанавливается через `npm run worker:secret` |

**Нет** `VITE_GITHUB_TOKEN` - это привело бы к утечке токена в браузерный бандл. Токен принадлежит Worker-у

## Как происходит загрузка профиля

```
User enters username
        │
        ▼
  Promise.all([
    fetchUser()           → Worker → KV hit? return.  miss → GitHub /users/{u}
    fetchRepos()          → Worker → KV hit? return.  miss → GitHub /users/{u}/repos
  ])
        │
        ▼ (параллельно, после получения репозиториев)
  Promise.all([
    fetchAllLanguages()   → Worker → KV per-repo /repos/{u}/{r}/languages  ×≤20
    fetchContributions()  → github-contributions-api.jogruber.de/v4/{u}
    fetchUserEvents()     → Worker → KV /users/{u}/events (2 страницы, до 200 событий)
  ])
        │
        ▼
  renderStreakGraph()     → D3 SVG тепловая карта
  renderCommitHeatmap()  → D3 7×24 сетка часов кодирования
  renderLanguageChart()   → D3 анимированные полосы
  renderTopRepos()        → HTML карточки
  renderHealthReport()    → полосы здоровья репозиториев (описание, лицензия, активность, темы)
  animateCount()          → счётчики статистики (requestAnimationFrame)
  updateRateLimitBadge() → fetch /rate_limit → обновление значка в шапке
```

Агрегация языков суммирует байты кода в до 20 недавно обновлённых репозиториев, затем конвертирует в проценты. Форки исключены - учитываются только оригинальные работы.

**TTL кэша** (настраивается в `worker/index.ts`):

| Маршрут | TTL | Почему |
|---|---|---|
| `/rate_limit` | 1 мин | Живая квота - должна быть свежей |
| `/users/:u` | 10 мин | Данные профиля (подписчики, био) меняются время от времени |
| `/users/:u/repos` | 10 мин | Список репозиториев меняется при публикации новых |
| `/users/:u/events` | 15 мин | Недавние push-события для тепловой карты часов кодирования |
| `/repos/:u/:r/languages` | 60 мин | Байты языков почти не меняются ежечасно |

Добавьте `?fresh=1` к любому запросу Worker-а, чтобы обойти кэш для одного вызова.

## Известные ограничения

- **Тепловая карта контрибуций** использует сторонний прокси (`github-contributions-api.jogruber.de`), поскольку GitHub предоставляет данные контрибуций только через GraphQL API с аутентификацией. Этот прокси иногда бывает недоступен
- **Статистика языков** отражает байты кода, а не количество файлов или потраченное время - та же методология, что и GitHub Linguist
- **Приватные репозитории** не видны - Worker использует токен с доступом только к публичным репозиториям
- **Первый запрос к холодному профилю** всё ещё требует ~20 вызовов GitHub (по одному на репозиторий для языков). Последующие загрузки в течение часа поступают из KV
